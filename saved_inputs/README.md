# Saved inputs for the instellation sweep

Each simulation in `archean_instellation_sweep.ipynb` has its own folder here, holding everything needed to
(1) restart the photochemical model from its converged state, (2) reproduce that state quickly, and
(3) plot the vertical structure (temperature, pressure, eddy diffusion and the mixing ratio of every gas). This file is generated by `make_readme()` from the `*_run.json` files, so it always matches what is saved.

## The scenario (same for every run)

- **Planet:** Earth's mass (5.972e+27 g) and radius (6.371e+08 cm), surface albedo 0.2, solar zenith angle 60 degrees.
- **Atmosphere:** anoxic. N2 fixed at 1 bar at the surface; CO2 fixed at the run's value (the lever the sweep adjusts); water vapour limited to 50% relative humidity with condensation above the cold trap; hydrogen escape at the diffusion limit.
- **Surface sources and sinks** (molecules cm^-2 s^-1; `vdep` is a deposition velocity in cm/s): H2 flux 3e10 (volcanic), CH4 flux 3e10 (biological), CO flux 1e9 with vdep 1e-8, SO2 flux 1e9, H2S flux 1e8, OCS flux 5e7, NO flux 3e8, NH3 flux 1.5e10, H2SO4 flux 7e8, HCN flux 1.7e8, CH3CN flux 1.3e8, O2 flux 0 (no oxygenic photosynthesis). The full list is in each run's `*_photochem_settings.yaml`.
- **What a run does:** for a given star and instellation, it finds the CO2 partial pressure that holds the surface at 288 K in the coupled climate (`AdiabatClimate`, radiative-convective equilibrium) and photochemistry (`EvoAtmosphere`) models, iterating until the CO2 pressure changes by less than about 5%. Climate and photochemistry exchange the surface CH4, H2, CO2 and N2 abundances and the temperature profile.
- **Software:** Photochem 0.9.1, Python 3.11.18. The chemistry is a Zahnle-network subset with H, He, N, O, C and S (`shared/mechanism.yaml`); the climate model uses H2O, CO2, N2, CH4 and H2 (`shared/climate_species.yaml`).
- **Solver settings that matter for a restart:** integrator absolute tolerance 1e-18 (Photochem's default is 1e-23, which is millions of times slower for cold, CO2-rich cases), maximum steps before giving up raised to 1,000,000, and a persistent pressure-based temperature and eddy-diffusion profile (see `*_PTKzz_profile.txt`). A run counts as steady when Photochem's own criterion is met or the surface mixing ratios of CO, O2, H2O, CH4, H2 and CO2 change by less than 1% over the last decade of model time (trace species below 1e-12 are compared in log space).

## File names

A run is identified by a name like `Sun3Ga_S1400.00_CO2-4.651e-05bar`:

| Part | Meaning |
|---|---|
| `Sun3Ga` | the Sun as it was 3 billion years ago (`Sun` at age 3 Ga: Photochem's bundled ATLAS-1 solar spectrum, scaled in the past with the Claire et al. 2012 young-Sun routine, with a 5778 K blackbody added at long wavelengths) |
| `GJ876` | the M dwarf GJ 876: observed MUSCLES spectrum (MAST archive) with a blackbody added at long wavelengths |
| `S1400.00` | **S**, the total stellar instellation at the planet in W/m^2. The spectrum's shape is fixed and its scale is set so its integral equals this value |
| `CO2-4.651e-05bar` | the CO2 partial pressure at the surface, in bar, in scientific notation (`6.003e00` means 6.003 bar; `4.651e-05` means 0.00004651 bar), as the lower boundary condition for CO2. For runs where 288 K is not reachable this is the capped or maximum-greenhouse value; for runs with no steady state it is the value that was attempted |

Each run folder `saved_inputs/<run name>/` holds these files, each starting with the run name:

| Suffix | Contents |
|---|---|
| `_run.json` | metadata: star, instellation, CO2, outcome flags, the iteration history, surface mixing ratios, parameters, versions |
| `_photochem_atmosphere.txt` | final photochemical state in Photochem's atmosphere format: `alt` (km), `press` (bar), `den` (molecules/cm^3), `temp` (K), `eddy` (cm^2/s), then the mixing ratio of every particle and gas, then particle radii (`*_r`, cm). Layers run from the surface upward. Mixing ratios are saved to 10 decimals |
| `_photochem_settings.yaml` | Photochem settings file with this run's CO2 lower boundary (planet, grid, boundary conditions, particles) |
| `_flux.txt` | stellar flux used (wavelength in nm, flux in mW/m^2/nm) |
| `_PTKzz_profile.txt` | the pressure-based temperature and eddy-diffusion profile the last photochemical solve ran on: pressure (dyn/cm^2, surface first), temperature (K), Kzz (cm^2/s); the header records the tropopause pressure and target top-of-atmosphere pressure |
| `_climate_profile.txt` | the final radiative-convective profile from the climate model for the final composition: layer pressure (bar), temperature (K), altitude (km), whether the layer convects with the one below, and the mixing ratio of each climate species; the header gives the surface temperature, surface pressure and tropopause pressure |

`saved_inputs/shared/` holds files common to all runs: `mechanism.yaml`, `climate_species.yaml`, `climate_settings.yaml`, and the downloaded GJ 876 spectrum (`GJ876_muscles_raw.npz`, so the flux can be rebuilt offline). `mechanism_haze.yaml` is the same network with the haze-forming reactions kept (used by the `_haze` runs).

**Haze runs.** A name ending in `_haze` is a rerun with Photochem's haze chemistry switched on (`haze=True`): the reactions `C2H + C4H2 -> HCaer1 + H`, `H2CN + HCN -> HCaer2` and `C4H + HCCCN -> HCaer3` are kept, so hydrocarbons and nitriles are removed as haze particles (`HCaer1-3`, default radius 1e-4 cm). `_hazeR1e-5cm` means the same with an explicit haze particle radius of 1e-5 cm. Haze acts in the photochemistry only; the climate model ignores haze optical effects. These reruns replace the no-haze GJ 876 runs that had no steady state (same star and instellation, no suffix). Haze carbon-loss rates are in `haze_diagnostics.csv`.

The photochemical profile (`_PTKzz_profile.txt`) and the final climate profile (`_climate_profile.txt`) can differ. The photochemistry ran on the profile computed *before* its final composition was known; the climate profile is then recomputed for the final composition, and its surface temperature is the one reported as `T_surf`. For the 31 runs that hold 288 K the two surface temperatures agree to within 0.70 K (median 0.10 K). For the 8 steady runs where 288 K is not reachable they differ by up to 31 K (6 of them by more than 1 K): the CO2 is pinned at the cap, so the loop stops changing CO2 and counts as converged while the climate recomputed for the final composition is still moving. Treat the compositions of those runs as indicative only.

## Restarting a run

```python
from sweeplib import reproduce_run, load_climate, read_profile

rid = 'Sun3Ga_S0850.00_CO2-3.064e-01bar'          # any folder name in saved_inputs/
pc, report = reproduce_run(rid)                   # rebuilds the model from the saved files; converged state in seconds (3 to 81 s across the saved runs)
print(report['max_rel_diff_tracked'])             # how closely it matches the saved surface composition
atm = pc.mole_fraction_dict()                     # vertical profiles: 'pressure', 'temp', 'CO', 'CH4', ... for plotting
clim, ok = load_climate(rid)                      # rebuilds the climate model state (restarts the RCE solve)
```

Runs flagged `NO STEADY STATE` have nothing to converge to: restarting one simply keeps running away, which `reproduce_run` reports. Their files are kept for diagnosis only.

`sweeplib.py` is written by the sweep notebook (cell 2 in `archean_instellation_sweep.ipynb`) and is also committed next to it. The notebook `reproduce_saved_runs.ipynb` shows the whole workflow, including plotting vertical profiles straight from the text files without the model.
